# FHIR Service Request Bundle to DICOM Modality Worklist Strategy

When mapping a FHIR imaging order bundle to a DICOM Modality Worklist (MWL / C-FIND response), the information is projected across the standard DICOM Information Model hierarchy: **Patient**, **Imaging Service Request**, **Requested Procedure**, and **Scheduled Procedure Step (SPS)**.

---

### 1. Patient Identification & Demographics

Data from the **`Patient`** resource populates the DICOM Patient-level module.

| FHIR Element | DICOM Tag | DICOM Attribute Name | Mapping Notes |
| --- | --- | --- | --- |
| `Patient.identifier` | `(0010,0020)` | Patient ID | The primary institutional MRN. |
| `Patient.identifier.assigner` | `(0010,0021)` | Issuer of Patient ID | System or clinic issuing the MRN. |
| `Patient.name` | `(0010,0010)` | Patient's Name | Formatted as `Last^First^Middle^Prefix^Suffix`. |
| `Patient.birthDate` | `(0010,0030)` | Patient's Birth Date | Formatted as `YYYYMMDD`. |
| `Patient.gender` | `(0010,0040)` | Patient's Sex | Mapped to `M`, `F`, or `O`. |
| `Patient.extension[patient-birthTime]` | `(0010,0032)` | Patient's Birth Time | Optional; formatted as `HHMMSS`. |

---

### 2. Order & Visit Context

Data from **`ServiceRequest`**, **`Encounter`**, and **`Practitioner` / `PractitionerRole**` populates the Imaging Service Request and Visit Identification modules.

| FHIR Element | DICOM Tag | DICOM Attribute Name | Mapping Notes |
| --- | --- | --- | --- |
| `ServiceRequest.identifier` | `(0008,0050)` | Accession Number | Critical tracking identifier assigned by RIS/EHR. |
| `ServiceRequest.identifier` | `(0040,2016)` | Placer Order Number / Imaging Service Request | When tracking Placer vs. Filler IDs separately. |
| `ServiceRequest.requester` | `(0008,0090)` | Referring Physician's Name | From referenced `Practitioner.name`. |
| `ServiceRequest.reasonCode.text` | `(0040,1002)` | Reason for the Requested Procedure | Clinical indication or chief complaint. |
| `Encounter.identifier` | `(0038,0010)` | Admission ID | Visit number or financial billing number. |
| `Encounter.location` | `(0038,0300)` | Current Patient Location | Inpatient nursing unit, bed, or clinic room. |

---

### 3. Requested Procedure Module

`ServiceRequest` represents the high-level procedure requested by the clinician.

| FHIR Element | DICOM Tag | DICOM Attribute Name | Mapping Notes |
| --- | --- | --- | --- |
| Synthetic / Workflow Engine | `(0020,000D)` | Study Instance UID | Generated by the broker/RIS to link future images. |
| `ServiceRequest.code.text` | `(0032,1060)` | Requested Procedure Description | Human-readable procedure name (e.g., "CT Abdomen"). |
| `ServiceRequest.code.coding` | `(0032,1064)` | Requested Procedure Code Sequence | LOINC, CPT, or local hospital order code. |
| `ServiceRequest.priority` | `(0040,1003)` | Requested Procedure Priority | Maps `stat` $\rightarrow$ `STAT`, `routine` $\rightarrow$ `ROUTINE`, etc. |
| `ServiceRequest.id` | `(0040,1001)` | Requested Procedure ID | Often set to the ServiceRequest ID or order item ID. |

---

### 4. Scheduled Procedure Step (SPS) Sequence `(0040,0100)`

A single `ServiceRequest` may generate one or more Scheduled Procedure Steps (e.g., a two-part exam). These attributes live inside the items of the **Scheduled Procedure Step Sequence**.

| FHIR Element | DICOM Tag | DICOM Attribute Name | Mapping Notes |
| --- | --- | --- | --- |
| Unique SPS ID | `(0040,0009)` | Scheduled Procedure Step ID | Unique identifier per protocol/step within the order. |
| `ServiceRequest.bodySite` | `(0040,0007)` | Scheduled Procedure Step Description | Detailed description for the modality technologist. |
| Extracted / Configured | `(0008,0060)` | Modality | DICOM modality code (`CT`, `MR`, `US`, `XA`, `CR`, `DX`). |
| `ServiceRequest.occurrenceDateTime` | `(0040,0002)` | Scheduled Procedure Step Start Date | Date part formatted as `YYYYMMDD`. |
| `ServiceRequest.occurrenceDateTime` | `(0040,0003)` | Scheduled Procedure Step Start Time | Time part formatted as `HHMMSS`. |
| Extracted / Configured | `(0040,0001)` | Scheduled Station AE Title | Specific scanner AE title targeted to perform the study. |
| `ServiceRequest.performer` | `(0040,0006)` | Scheduled Performing Physician's Name | If a specific radiologist is assigned to oversee. |
| `ServiceRequest.code.coding` | `(0040,0008)` | Scheduled Protocol Code Sequence | Protocol code recognized by the scanning modality. |

---

### 5. Medical Alerts & Clinical Context

Data from supplemental clinical resources flags safety alerts and pre-procedure considerations.

| Source Resource | FHIR Path | DICOM Tag | DICOM Attribute Name |
| --- | --- | --- | --- |
| **`AllergyIntolerance`** | `substance.coding` / `text` | `(0010,2110)` | Contrast Allergies |
| **`Observation`** | Pregnancy status | `(0010,21C0)` | Pregnancy Status |
| **`Observation`** | Patient weight / size | `(0010,1030)` / `(0010,1020)` | Patient's Weight / Size |
| **`Condition`** | `code.text` / `category` | `(0010,2000)` | Medical Alerts |
| **`Device`** | Implants / pacemakers | `(0010,21B0)` | Additional Patient History |

## Technology Stack
